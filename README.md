# Мир Тачек

Сайт и учетная система для продажи автозапчастей, автотоваров и услуг СТО. В ней работают покупатели, магазины, дилеры и администратор.

Это чистый HTML, CSS и JavaScript без сборки. Сайт работает на GitHub Pages, Firebase Hosting или любом статическом хостинге. Данные хранятся в Firebase (Auth и Firestore) на **бесплатном тарифе Spark**.

---

## 1. Роли

| Роль | Что видит и делает |
|---|---|
| **Гость** | Каталог, избранное, корзина. Заказ отправляется в WhatsApp. |
| **Покупатель** | Получает эту роль автоматически при первом входе. Оформляет заказы и договаривается с админом в WhatsApp о самовывозе или доставке. Видит свои заказы и чеки. |
| **Магазин** | Видит цены для магазина. Заказывает у компании на дату. Принимает отгрузки от компании и дилеров, подтверждает или оспаривает оплаты. Видит свой отчет по поставщикам. |
| **Дилер** | Видит дилерские цены и цены для магазинов. Заказывает товар у компании на дату, получает выдачи, отгружает магазинам со своего товара. Видит свой отчет и отправляет его администратору. |
| **Администратор** | Видит всё: пользователей и роли (включая назначение администраторов), заказы, документы, оплаты, расхождения, мини-1С с диаграммами, склад, CRM, настройки и журнал. |

Роль меняет только администратор: **Управление → Пользователи**. Правила Firestore не дают пользователю поменять роль самому себе.

## 2. Логика товара и денег

| Документ | Кто оформляет | Цена | Склад компании |
|---|---|---|---|
| Розничная продажа | Админ (по заказу покупателя) | Розница | Списывается |
| Отгрузка магазину со склада | Админ | Цена магазина | Списывается |
| Выдача дилеру | Админ (по заказу дилера) | Цена дилера | Списывается |
| Отгрузка дилера в магазин | Дилер | Цена магазина | Не трогается: уходит из товара на руках у дилера |

- **Товар на руках у дилера** = выдано ему − отгружено им. Считается автоматически.
- **Маржа дилера** = цена магазина − цена дилера.
- **Выручка компании** = продажи + отгрузки со склада + выдачи дилерам. Маржа считается по цене закупа.

### Оплаты: двустороннее подтверждение

1. Любая оплата сначала попадает в статус **«ждет подтверждения»**. Ее может указать продавец («получил») или покупатель («оплатил»).
2. Подтвердить оплату может **только вторая сторона**. Это проверяют правила Firestore.
3. Если вторая сторона отвечает «не было», документ получает статус **«Расхождение»**. Его видят обе стороны и администратор, а решает администратор: признать оплату или аннулировать.
4. Долги и отчеты считаются **только по подтвержденным деньгам**. Поэтому отчет дилера и отчет магазина всегда совпадают.
5. Оплаты, которые вносит администратор, подтверждаются сразу: он ведет кассу компании.

### Заказы на дату

- Магазин и дилер заказывают у компании на нужную дату (по умолчанию на завтра).
- Заказ магазина видят магазин и администратор, заказ дилера — дилер и администратор.
- Администратор может выполнить заказ магазина сам или **передать дилеру**. Тогда дилер увидит заказ и оформит отгрузку по нему.
- **Сборочный лист** показывает, сколько каждого товара собрать на дату и чего не хватает на складе.

## 3. Структура проекта

```
index.html              разметка-каркас
css/styles.css          стили (без эмодзи, только SVG-иконки)
js/config.js            настройки Firebase, email владельца, размеры страниц
js/utils.js             форматирование, даты, CSV/XLSX, файлы
js/icons.js             SVG-иконки
js/ui.js                модальные окна, уведомления, пагинация, диаграммы
js/state.js             справочники ролей и статусов, состояние интерфейса
js/data.js              DataLayer: Firebase (LIVE) или localStorage (демо)
js/domain.js            расчеты: цены, видимость, оплаты, долги, отчеты
js/services.js          операции записи: заказы, документы, оплаты, каталог, склад, роли
js/views/catalog.js     каталог, карусель, избранное, заявка на консультацию
js/views/cart.js        корзина и оформление для всех ролей
js/views/orders.js      заказы, передача дилеру, сборочный лист
js/views/docs.js        документы, приемка, оплаты, расхождения, печать
js/views/reports.js     мини-1С, отчеты дилера и магазина, Excel/CSV/печать
js/views/crm.js         CRM, WhatsApp-сценарии, просмотры, заявки
js/views/manage.js      пользователи и роли, товары и Excel-импорт, склад, настройки, журнал
firestore.rules         права доступа (главная защита данных)
storage.rules           права на фото
firebase.json           настройки Firebase Hosting и правил
templates/mir-tachek-shablon-kataloga.xlsx   шаблон каталога с примерами
```

Пагинация есть во всех списках. Все данные загружаются один раз через подписки, а страницы листаются без перезагрузки.

## 4. Шаг 1: GitHub Pages

1. Создайте репозиторий на GitHub, например `mir-tachek`, и загрузите в него **содержимое** архива (`index.html` должен лежать в корне репозитория).
2. Откройте **Settings → Pages → Build and deployment → Source: Deploy from a branch**, выберите ветку `main` и папку `/ (root)`, нажмите **Save**.
3. Через 1–2 минуты сайт откроется по адресу `https://ВАШ_ЛОГИН.github.io/mir-tachek/`.
4. Пока Firebase не подключен, сайт работает в **демо-режиме**: данные хранятся в браузере, а в шапке можно переключаться между пользователями (админ, дилеры, магазины, покупатель) и проверить все сценарии.

Файл `.nojekyll` уже лежит в архиве: он нужен, чтобы GitHub отдавал файлы как есть.

## 5. Шаг 2: подключение Firebase (общая база для всех)

1. Зайдите на https://console.firebase.google.com, создайте проект и добавьте **Web app**. Скопируйте объект `firebaseConfig`.
2. Вставьте значения в `js/config.js` → `FIREBASE_CONFIG`.
3. Впишите свой email в `js/config.js` → `ADMIN_EMAILS` **и** в `firestore.rules` в функцию `bootstrapAdmin()` вместо `owner@example.com`.
4. **Authentication → Sign-in method:** включите **Google** и **Email/Password**.
5. **Authentication → Settings → Authorized domains:** добавьте `ВАШ_ЛОГИН.github.io`, а позже и свой домен.
6. **Firestore Database → Create database** (production mode). Во вкладке **Rules** вставьте содержимое `firestore.rules` и нажмите **Publish**.
7. Загрузите изменения на GitHub. Откройте сайт и войдите своим email: вы сразу станете администратором.
8. Откройте **Управление → Настройки** и укажите WhatsApp компании (например `77001234567`). Затем в **Управление → Товары** скачайте шаблон, заполните его и загрузите весь каталог одним файлом.
9. Пусть магазины и дилеры войдут на сайт. После этого назначьте им роли в **Управление → Пользователи** и задайте магазинам уникальные названия.

### Фото товаров

- **Ссылка на фото** работает всегда.
- **Загрузка файла.** Если Firebase Storage включен (на новых проектах для этого нужен тариф Blaze), файл уходит в Storage. Правила лежат в `storage.rules`. Если Storage недоступен, фото сжимается до 800 px и хранится прямо в карточке товара. На тарифе Spark это работает без настройки.

## 6. Шаг 3: свой сайт (Firebase Hosting или домен)

**Вариант А: Firebase Hosting**

```bash
npm install -g firebase-tools
firebase login
firebase use --add            # выберите свой проект
firebase deploy --only hosting,firestore:rules
```

Сайт откроется на `https://ПРОЕКТ.web.app`. Свой домен подключается в **Hosting → Add custom domain**. Не забудьте добавить домен в Authorized domains.

**Вариант Б: свой домен на GitHub Pages.** В **Settings → Pages → Custom domain** укажите домен и пропишите у регистратора DNS-записи по инструкции GitHub.

## 7. Важно знать

- **Защита данных держится на `firestore.rules`.** Без опубликованных правил база открыта или закрыта целиком. Публикуйте правила при каждом изменении.
- **Цены скрыты по ролям** через отдельные прайс-листы (`priceLists/store`, `priceLists/dealer`, `priceLists/cost`). Закуп видит только администратор.
- **Печатные документы — внутренние.** Это не фискальный кассовый чек.
- **Мини-1С — управленческий учет**, а не бухгалтерский или налоговый.
- **Офлайн.** Firestore хранит копию данных в браузере (IndexedDB): последние загруженные данные открываются без сети, а изменения уходят на сервер после восстановления связи.
- **Перед запуском** проверьте роли на тестовом проекте Firebase и включите резервное копирование Firestore.
