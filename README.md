# МИР ТАЧЕК — объединённый проект

В проект объединены исходный сайт, каталог товаров и услуг, роли покупателей/магазинов/дилеров/администратора, оформление заказов и отгрузок, CRM, WhatsApp-сценарии, управленческие отчёты, складские операции, импорт/экспорт и печатные внутренние документы.

## Что теперь работает

- Google-вход и профиль пользователя; роли меняются только серверной Cloud Function администратором.
- Каталог с разными ценами по ролям, остатками, фильтрами, избранным, карточками, каруселью и загрузкой фото в Storage. В LIVE-каталоге цены выдаются сервером по роли: закупочная цена не передаётся обычным покупателям, дилерам и магазинам.
- Оформление розничного заказа, предзаказа и дилерской отгрузки. В LIVE-режиме цены, наличие и списание товара проверяются и проводятся атомарно на сервере.
- Отгрузка связывается с конкретным профилем магазина по уникальному названию профиля. Магазин может подтвердить приемку за наличные или в долг.
- Складской приход и списание с журналом движений; остатки изменяются серверной транзакцией.
- Частичная оплата с распределением суммы на наличные или перевод; отчёты отдельно считают эти каналы и задолженность.
- CRM-контакты, этапы и задачи. Для сценария просмотра за 7 дней контакт связывается с профилем клиента через поле Firebase UID.
- WhatsApp-номер компании задаётся администратором в настройках; доступны сообщения заказа, товара, новинки, долга и просмотра.
- Отчёты по периоду: выручка, себестоимость, валовая прибыль, наличные, переводы, долг и стоимость остатков; Excel/CSV/печать.
- Импорт/экспорт каталога CSV, JSON, XLSX.
- Локальное зеркало и очередь отложенной отправки обычных изменений при восстановлении сети.

## Запуск Firebase

1. Создайте проект Firebase и Web App.
2. В `js/firebase.js` замените все `YOUR_...` в `config` на значения вашего Firebase Web App.
3. В Authentication включите Google Sign-In и добавьте домен сайта в Authorized domains.
4. Создайте Firestore Database и Storage.
5. Для Cloud Functions 2-го поколения в Firebase обычно требуется тариф Blaze с подключённым биллингом. Установите Firebase CLI и войдите: `npm install -g firebase-tools`, `firebase login`, `firebase use --add`.
6. Назначьте первого администратора: сначала войдите в приложение через Google, затем выполните из каталога `functions` команду с сервисным аккаунтом Firebase Admin SDK:
   `GOOGLE_APPLICATION_CREDENTIALS=/path/service-account.json node set-admin.js FIREBASE_UID`
   Никогда не размещайте service-account JSON в папке сайта и не передавайте его браузеру.
7. Установите зависимости функций: `cd functions && npm install`.
8. Из корня проекта разверните: `firebase deploy --only firestore:rules,storage,functions,hosting`.
9. Войдите как администратор, откройте «Настройки компании» и задайте WhatsApp-номер в международном формате, например `77001234567`.
10. Назначьте роли магазинам и дилерам во вкладке «Пользователи». Название магазина в профиле должно быть уникальным — именно по нему сервер сопоставляет получателя отгрузки.

## Запуск локально

Откройте проект через локальный HTTP-сервер (не `file://`), например `python -m http.server 8000`, затем перейдите на `http://localhost:8000`. Для реального входа и облачных функций всё равно нужны Firebase-конфигурация и авторизованный домен.

## Важные границы и то, что требует внешнего подключения

- В проекте нет подключения к банку/эквайрингу, платёжной системе или фискальному оператору. Печатаемый документ помечен как внутренний и **не является фискальным кассовым чеком**.
- Мини-1С — управленческий оперативный учёт, а не полноценный бухгалтерский, налоговый или регламентированный учёт. Исторические документы старого формата могут не содержать себестоимость и разбивку оплаты, поэтому старые отчёты по прибыли/каналам оплаты могут быть неполными.
- Синхронизация оффлайн-изменений работает через локальную очередь повторной отправки; полноценного разрешения конфликтов между несколькими устройствами и совместного редактирования нет. Проведение продаж и складских операций в LIVE требует связи и не ставится в очередь.
- CRM-сценарий «просматривал 7 дней назад» работает только для вошедших клиентов, чьи просмотры сохранены, и если в карточке CRM заполнен точный Firebase UID клиента. WhatsApp открывает подготовленное сообщение; автоматическая рассылка без подтверждения пользователя не выполняется.
- Приход на склад фиксирует количество и основание, но полноценного закупочного процесса с поставщиками, счетами, оплатой поставщикам и возвратами пока нет.
- Перед реальным запуском обязательно протестируйте роли и правила в Firebase Emulator/тестовом проекте, проверьте резервное копирование Firestore и настройте мониторинг Cloud Functions.

## Структура

- `index.html`, `css/styles.css` — интерфейс.
- `js/app.js` — каталог, корзина, CRM, документы, отчёты, склад и локальная синхронизация.
- `js/firebase.js` — конфигурация и SDK Firebase.
- `functions/index.js` — серверное проведение документов, приемка, управление ролями и складские транзакции.
- `functions/set-admin.js` — безопасное первоначальное назначение администратора через Admin SDK.
- `firestore.rules`, `storage.rules` — правила доступа.
